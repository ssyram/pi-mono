# provider-profiles — 独立对抗测试计划

## 当前适用版本（2026-09-22）

本文件的主体是 Astra 在产品实现前写出的独立基线计划，保留其原始判据与反例设计；它**不是当前实现的逐字规格**。当前适用的 QPD 以 `principles.md`、`architecture.md`、`detailed.md` 为准，执行证据以 `test-results.md` 为准。以下基线中已被后续用户裁决和实现取代的部分：

- 来源不再固定为三种：C2 动态支持全部不带 `refreshModels` 的内置来源，OAuth/API-key 与 Copilot filter 转发由工厂分类决定。
- 实例名不再因任何同名 models.json 键被拒：只有会进入认证/路由/请求头的危险同名内容拒绝；纯 `modelOverrides`（无模型级 `headers`）有意保留。
- 产品已实现；原文中的“尚不存在”“待绑定”应读作当时的测试设计状态。
- C5 `/add-login`、profile 原子写入、动态 fuzzy 补全是后续 D/I；其测试在执行记录中。

原计划的 T 编号仍是溯源索引；若与上述当前规范冲突，以上述规范为准。

## 判据来源、范围与读法

唯一判据来源为同目录的 `principles.md` 与 `architecture.md`。未读取产品实现、`detailed.md`、其他设计或宿主源码；本文不规定产品函数名、导入语句、配置外层结构或新的配置字段。

- 共 **34 个测试编号**：T-01–T-32 是规范判据，T-33–T-34 是未闭合事实的观察协议。参数化子例不另计数。
- AT-01–AT-16 是复用这些编号的对抗执行轨迹，不另计测试数量。
- “P1”至“P7”分别指 `architecture.md` 的 `P.local.1` 至 `P.local.7`；C1–C4 指其组件 contract。
- **历史状态**：原计划写作时产品尚不存在，以下主体是当时的待实现/待绑定设计，不是当前执行通过报告。当前测试结果以 `test-results.md` 的“当前状态”为准；无法绑定的测试仍应记为“阻塞/未执行”，不能记为通过。
- 使用同一宿主版本、同一时刻取得的官方工厂及目录作为独立参考。禁止把待测实例自己的模型输出再当作“官方预期值”，也不把 Q.E.1 的历史数值当作永久模型参数。
- 测试账号、环境 key、存储 key 使用可区分的合成标记。证据只记录来源标签和槽位，不输出真实凭据。测试夹具自身的写入、注入与被测动作分开记账。
- 除明确研究重载的 T-34 外，失败与零注册断言默认从没有本插件实例的隔离宿主启动；观察注册的整个过程，而不只看最终注册表。这样不把 T2 尚未确定的旧实例清理行为冒充已定义保证。
- “可见错误”指用户可观察到的诊断，条目级诊断须能识别原条目名。只写入用户看不到的内部状态不算可见；具体出口、格式与数量见 G-05。
- “不可用”必须同时检查认证解析结果和真实可用模型入口，不能仅凭注册表中没有某项推断。按 Q.A.4，未认证实例仍可已注册、仍可具有模型目录。
