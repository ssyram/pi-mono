# AI 学习原则

## 引用修饰符 — 发送识别与补全触发分开

- **来源**：用户确认带空格冒号作为自动补全入口，并补充发送时 `/name:print` 与 `/name :print` 等价；无法直接加载真实资源时不得替换。
- **原则**：编辑器的触发限制不能反向收窄发送语法。自动触发只负责发起补全请求，插件必须结合前方完整资源引用及唯一精确加载结果决定是否认领；发送识别允许零个或任意多个横向空白，不能把候选列表当作资源本体。
- **边界**：不跨行关联；未解析引用逐段原样保留。文件修改严格限于 `my-plugins/`，不因记录学习或解决编辑器限制扩大写入范围。

## pi 对接 — 先论证可恢复异常与合法返回，再实现

- **来源**：用户在实现前要求补齐函数级规约，并明确所有 pi 对接函数不得抛出或返回会破坏框架的非法值。
- **原则**：为每个直接回调规定精确返回集合、异常收束和 fallback；下层 provider 的返回值必须归一化，异步 rejection 必须被 await 所在边界捕获。仅 catch 自己的逻辑而原样透传第三方结果，不能证明框架安全。
- **边界**：基础模块测试安装 provider 不等于正式接入；入口、事件注册与指引修改必须保持未接入状态，不能把实现授权扩展到未授权链路。

## 写入式检查 — 显式列出本次文件，不依赖配置过滤

- **来源**：本轮格式化检查的配置过滤未按预期生效，目录级写入误改现有文件；随后撤回格式改动并保留已有工具描述修改。
- **原则**：共享工作树中的写入式工具必须接收本次拥有文件的明确路径，配置过滤只能作为第二层限制。发生越界时先保存真实状态，仅还原本次工具引入的改动，不重置既有修改。
- **边界**：配置或检查命令退出成功不证明作用域正确；禁止通过全仓写入检查扩大用户限定的修改范围。

## CCA 运行 — 使用用户修正后的渠道，不沿旧假设继续拼接

- **来源**：用户指定 tmp-haokun/glm-5.3-flash，并说明该渠道问题已修正，可直接运行，无需继续查找或拼接凭据。
- **原则**：用户明确修正环境事实后，停止旧假设驱动的凭据查找，使用指定渠道做真实最小请求；给 CCA 只提供目标与标准 FSM 入口，不附加分析策略、拆分或推进指示。完成后再依据原意审核 PRE/POST，不用运行成功冒充函数正确。
- **边界**：测试通过、模型冒烟成功、CCA 终态与函数契约成立是不同证据；只读监控不授权替答权限、修改源码或更换执行协议。

## CCA 监控 — 空 FSM 重复调用是停滞，不是正常等待

- **来源**：旧 run 在 inactive 默认帧持续重复 GET STATE，无 manifest、函数产物或入口调用；用户指出卡死并授权停止重跑。
- **原则**：模型冒烟与请求接收不等于进入分析 FSM；启动成功必须绑定已进入目标 FSM 的证据。连续相同状态且无目标产物时明确报停滞并提出停止建议，不以进程存活、无 APIError 或权限为空代替进展。
- **边界**：未获干预授权时不能偷偷修状态、改模型或发追加指示；获停止重跑授权后，仅停止本次专属进程，保留失败证据，在相同输入与协议下重新验证入口。

## OC permission — 隔离数据不隔离用户既有授权

- **来源**：用户指出全局早已允许一切；隔离配置漏掉原生 permission 却被当成需要再审批，并要求修改两个 skill 的默认规则。
- **原则**：默认保留 OC 原生全局/项目/会话 permission 解析；用原生附加配置隔离运行数据，不建立 broker、不代答、不把配置继承错误转成重复授权。只有用户明确要求排除全局授权时才另设策略。核对原生配置时按等价归一化判断，例如 allow 与星号 allow 映射。
- **边界**：这不绕过 FSM 门禁，不扩大分析或修改源码的授权；仅沿用已有权限。观察器按生产者真实 manifest 合同读取记录列表及 function kind，不凭猜测假定字典 schema。

## pi provider 契约 — 返回值合法性是 provider 的责任，框架不兜底

- **来源**：用户质疑 F1 是否 pi 负责；核 editor.ts：applyCompletion 返回的 lines/cursor 被直写进编辑器状态，setCursorCol 无范围检查，两个选择入口无形状校验。
- **原则**：包装或实现 provider 时不得以“框架会钳制/校验返回值”为前提；返回前自行保证光标界内、形状合法。同步方法误返回 thenable 时，其拒绝不会被同步 catch 收束，需显式接住（Promise.resolve(x).catch）。
- **边界**：该结论来自当前 tui 源码，不排除上游未来加校验；不得反向依赖。

## CCA 审定 — 用可运行反例裁决契约，不信完成标记

- **来源**：父审对照 32 份 fn 报告与源码、pi 调用链，用有限反例推翻多条 CCA 声明成立的 POST（越界光标、逃逸异常、空 items、非绝对路径）。
- **原则**：结构类型合法值不隐含未声明的额外前提——数组不保证标准迭代器语义，返回可变对象引用使字段保证在读取后失效，同步 catch 不收束错误 thenable 的后续 rejection，getter 可在多次读取间异变。审定契约时先写最小反例再下结论；CCA 的 aligned/0-unknown/门禁通过只证明流程完成。
- **边界**：反例只证伪对应 POST，不证明常规数据路径崩溃；普通稳定数据场景的既有测试仍有效。报告中的事实性数字（如字符集大小、limit 边界）也要复核，不能照抄。

## FSM 终态判定 — 按最终提交与 frame 退出，不按历史文本子串

- **来源**：监控用全文匹配 RUN_STATUS 标记，把 run 早期文本里的 BLOCKED 误当最终状态；实际正常边 A_DISPATCH_CLOSE→A_DONE 已 accept、frame 已退栈。
- **原则**：终态判定依据是最后一条 assistant 报告加 committed transition 序列（含被拒后重试的同一正常边），历史文本中出现过的标记不携带终态语义。
- **边界**：被拒的 transition 是修复路径的一部分，不构成失败证据；只有 A_FAILURE_REVIEW 边或最终报告明示才按阻塞处置。
