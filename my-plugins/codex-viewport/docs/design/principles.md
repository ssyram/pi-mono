# codex-viewport 原则

状态：已按用户反馈收敛

## Q.I — 核心意图

### 追求

- TUI 在内容持续生成或工具仍在执行时保持稳定，不因反复重画既有历史而闪烁。
- 流式输出期间的用户输入必须稳定；进程存活、输入正确和历史单份优先于绝对零重绘。
- 尚未完成的工具与非纯文字动态内容只更新当前可见区域；普通连续纯文字输出保持原生行为，完成后的内容成为稳定历史。
- 并行产生的内容即使乱序完成，最终历史仍保持原有语义顺序。
- 历史中每项内容只有一份，不出现重复、残留的中间版本或完成后仍不一致的旧版本。
- 用户主动展开工具输出时，TUI 可以重新呈现相关历史内容。
- 方案只调整 TUI 动态绘制，不全面接管原 TUI。

### 保护

- AI 能看到的内容、调用工具的行为、运行结果和会话数据必须与未安装插件时完全相同。
- 插件只能改变显示方式，不能通过改变 AI 或会话数据来修补显示问题。
- agent 不在运行时，TUI 的可见行为必须与原 TUI 100% 一致。
- 从运行进入静止的任何路径，以及从启动、重载、切换或恢复进入静止的任何路径，都必须得到相同的原生静态结果。
- 停机或崩溃后的下一次载入必须只反映原系统实际保存的数据，不恢复上次运行中仅用于显示的临时状态。
- 插件自身发生错误时，AI 运行不能因此改变；显示应退回原 TUI。
- 中文及其他复杂输入法的 composition、候选窗口和提交不能因插件的终端 ownership 而错位、重复或导致退出。
- 实现应尽量复用原 TUI 的消息、工具、编辑器和终端能力，降低维护成本。

### 不接受

- 运行期间因动态内容更新而反复重画已有历史。
- 同一条历史出现多份，或历史中保留未完成时的临时版本。
- 为压制 redraw 而接管终端 cursor/baseline，造成输入期间的物理重复、光标失配或进程退出。
- 并行内容按实际完成先后破坏原有语义顺序。
- agent 已停止但 TUI 仍处于插件控制、近似原生或残留临时状态。
- 停机、重载、恢复、切换会话或异常退出后出现与原系统不同的数据或静态显示。
- 为实现防闪烁而改变 AI 输入、上下文、工具调用、结果、持久化或后续模型行为。
- 像全面接管式方案一样重新实现整套 TUI。

## Q.A — 用户提供的认知

- 闪烁的主要可见原因是动态输出期间反复重画已经存在的历史。
- 未完成内容与完成历史应采用不同的绘制策略：前者只需更新可见区域，后者需要成为稳定历史。
- 并行内容可能后完成前面的项、先完成后面的项，因此“某项完成”不等于“它之前的全部内容都可以进入稳定历史”。
- 用户主动展开工具输出是需要重新呈现历史的合理场景。
- 防重复与防闪烁必须同时成立；不能用减少重画换来旧历史，也不能用完成后全量重画掩盖中间状态。
- Codex CLI 的整体体验符合目标方向。
- 重复历史式方案和全面接管式方案都不可接受。

## Q.E — 用户经验

- 类似 Claude Code 的一些显示方案会产生历史重复。
- 类似 OpenCode 的全面接管方案实现和维护成本过高。
- 仅通过降低历史重画频率不能解决完成历史最终一致性问题。
