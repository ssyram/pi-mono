# AI 学习原则

## 2026-10-23 — 委派能力要同时符合工具配置、角色规则和交付阶段

- **来源**：初次负责人使用 explore；静态清单列出 Bash，但角色正文禁止 Bash，无法读固定 Git dev 对象。用户随后明确要求调查、制作剧本/框架并完成 HC collect/replay 两次实跑，而非只交前期报告。
- **原则**：派遣前同时核对实际工具、角色禁止项与当前交付；从只读调查扩成制作和执行时，换成有相应权限的明确角色并交接，不让旧角色绕过规则或反复撞权限。长任务显式配置运行期限，超时保留原记录并续同一有效合同，不能把期限当作业务完成。
- **边界**：本包独立于 Pi/fsm-compatible/Nico；负责人可写本包、执行隔离命令并受限派出只读子调查。参考仓库与全局配置只读。完成必须有真实 HC collect 和独立 replay 证据；角色完成通知、调查报告或已有临时采集通过均不能替代。

## 2026-10-23 — collect 是受约束的基准采集，不是接受任意观测

- **来源**：用户规定 PLOT 记录剧本、预期错误与采集项，use-plot 负责 collect 与默认 replay，以及检查和 FSM 内部状态查询。
- **原则**：行为剧本与基础设施分离；collect 同样检查预先定义的约束，只有完整通过才能冻结 golden。replay 不改写基准；首次不一致必须失败锁存、返回可观察错误并停下实验，不由宿主重试或重新录制洗掉。
- **边界**：动态身份、时间、随机值及并发顺序的处理必须显式声明且保留原始证据；不做无依据的整段忽略或宽松多格式接受。不用脚本自写 marker 冒充被测 FSM 完成，不把有限覆盖称为全域正确。
