# AI 学习原则

## 2026-10-23 — 已有明确兼容基准时，先提取原生接口而不是自拟行为

- **来源**：用户明确要求调查当前 `../haokun-code` 的 SubAgent 能力及各接口与 FSM 的真实交互，逐项一比一提出复刻要求；此前先定义派工状态、停止分类和默认通知策略，偏离了既有 OC/HC 兼容基准。
- **原则**：兼容任务先锁定对端版本、真实注册入口、入参/返回、权限、生命周期、通知和错误调用链，再提取本地义务。实现无关不等于来源无关；不以自拟理想行为、现有适配实现或候选执行框架反向规定参考端需求。
- **边界**：将原自拟交互草案明确停止推进，保留历史但不作实施依据。调查子代理只交事实，主线程归纳源证规格；尚未确认的参考端行为保留未知，不擅自补齐、修正或声称已一比一兼容。用户此次要求不自动授权改实现或运行付费模型。

## 2026-10-23 — 实现调研不能替代主线程与用户的交互设计

- **来源**：用户纠正分工：子代理先调研事实；主线程直接完成实现无关的 SubAgent 设计，与用户共同讨论确认后，再讨论具体后端适配。此前把架构设计一并派出，混淆了事实研究与需求设计。
- **原则**：先按用户确定的责任归属组织工作。框架的现有 API、状态及限制只是适配输入，不反向规定应有交互；先清楚定义主体、派工、消息、等待、完成和异常责任，再将已确认契约映射到后端。设计草案中的新增默认取舍须标明待讨论，不冒充已接受需求。
- **边界**：本轮撤回委派架构任务，主线程交付后端无关草案；事实报告不构成设计批准、实现授权或运行证明。不因流程名自行追加审查，不在用户确认交互设计前展开具体适配。

## 2026-10-23 — 框架复用与故障恢复分别取证，不用活跃度代替推进

- **来源**：CCA6 监护曾用 spinner/context 增长判断正常；按真实 FSM toolResult 重建后，成功调用之后的一次迁移超时 300 秒，后续出现 3424 次 stream unavailable。此前初始化 rejected Promise 的归因与修复未覆盖已建通道失效。用户要求减少自研，试用 Nico 0.81 滚动后暂定该框架，除非有明显更优选项。
- **原则**：错误统计绑定 toolName、isError 与时间，不能把读取源码里的错误字符串算成运行故障。区分初始化失败与调用中失效；缓存已完成的初始化 Promise 不证明其内部 broker 仍可用。框架选择分别判断商用许可、内部 API、执行恢复与界面；不注册默认扩展不等于绕开执行内核的复杂性，更不保证稳定。
- **边界**：当前暂定固定 Nico 版本、不改上游源码、不注册其默认扩展，适配层提供 FSM 接口并要求无 TUI 可运行；这是选型与需求，不是实现或稳定性验收。迁移首次超时的内部原因仍未闭合；不自动重放可能已生效的 FSM 变更，不因研究结论杀会话或删除运行证据。

## 2026-10-21 — 共享根身份的真实多进程必须统一source所有权

- **来源**：实际OC/Pi对照中，child和parent均向同一root登记source，daemon在多个存活PID之间选winner，parent最终报source read-back mismatch: agent_pid；孤立child单测未暴露。修复为root维护actor通道并代理child的鉴权FSM调用后，完整共同场景及原v3通过。
- **原则**：身份scope、进程scope与lease scope分别定义；共享root不能由多个进程竞争同一source记录。准入、必载扩展与恢复必须沿实际启动路径测试，不能用旧模块或内部类测试代替当前入口。
- **边界**：固定场景一致不等于所有OC行为等价；不借此宣称B62在途裸写已安全。

## 2026-10-21 — 负例必须确实撞到指定hard gate，合法失败不能冒充验证成功

- **来源**：新增真实CCV交付场景时，缺toolchain_switch与错把key=value配置全文当switch均导致INFRA拒绝，不能计作frontend负例。读取真实配置字段后，实际CompCert报syntax error；空报告被failed_report_check拒绝，补全原因后V_FAILED→V_DELIVER→退出通过。
- **原则**：测试同时约束拒绝发生的validator和原因；区分脚本化judge/watcher verdict与真实hard-check执行。原v3只负责自身V_A_LOOP端点，不改原剧本制造全流程覆盖；独立失败交付保留gate-owned机器字段及证据，不手工伪造证明。
- **边界**：honest-failed交付不产cert，不证明V_VERIFIED链或真实模型评审能力。测试环境与输入副本隔离不授权修改上游源码、全局配置或真实用户工作区。

## 2026-10-21 — 能力保证必须来自当前入口的真实接线

- **来源**：用户要求分层说明fsm-compatible能保证什么。当前运行入口使用自带Agent，主要转发父CLI的-e参数；原准入/必载扩展/深度限制模块的存在及历史测试不能直接推出这条新启动路径也强制执行。普通permission错误拒绝与Stop错误放行也必须分开。
- **原则**：分别说明输入映射、通信身份、门禁、子代理控制、辅助协议及场景覆盖；实现、单元测试和整机跑通三类证据不得互相替代。未接线是实现保证缺口，不能都淡化成“只差补测”；同名命令不等于文件回滚或统计语义完全相同。
- **边界**：本轮交付收口、WS pop或126项测试不构成完整OC等价证明。最后入口整理后未重跑完整CCV应明确说明；不因解释能力范围自动启动修复、审查或新测试。

## 2026-10-21 — 收口依据回查原始transcript，不把验证边界自动变成新任务

- **来源**：用户要求按recalibration全pop并提醒查compact前transcript。原记录6084先披露v3完成而非全部15态及57秒未细分，6085明确批准commit/push；清理为6229起的独立追加委托，却只混写在FSM备注，未曾单建root。
- **原则**：以原始委托、已披露范围、实际回执及owner当前结束裁决判断本轮收口，不把AI追加的更广验证当新验收门槛。漏建独立工作线应明确在当前补录，不能伪造历史。验证适用边界与未完成目标分别记录；Done不得带未履行义务，也不能把真实未完成义务改名藏到备注。
- **边界**：发布批准及本轮结束不等于未测功能全域正确；原始完全兼容目标和关键限制保留。未来加强或扩大验证需另行委托，不因全pop抹去证据、边界或历史。原版CCV v3设计明确以Main仍在V_A_LOOP为端点；未去V_DELIVER是剧本覆盖范围，不是此次执行未完成，解释时不得把两者混写。

## 2026-10-21 — 保留必要性取决于当前用途和独有成果，不取决于功能是否存在

- **来源**：用户将问题明确为“保留是否必要”，并要求比较官方覆盖与上游维护。官方1.3.0的分类、codemode和用户交互shell示例，与逐条工具摘要或agent控制PTY不是同一功能；但缺少官方覆盖也不意味着必须保留第三方源码克隆。
- **原则**：分别判断当前运行依赖、用户独有修改/实验成果、上游可重新获取性及维护状态。干净的公开源码副本与必须安装的扩展分开；组件API或官方示例不能冒充默认内置完整功能。维护判断看实质提交与发布，不只看pushed_at。
- **边界**：建议不保留不是删除授权；用户独有实验材料不因运行不需要就当作无价值。原型无独立上游时，不凭目录日期宣称已停止维护。

## 2026-10-20 — 忽略目录不是实验材料与正式检查之间的隔离

- **来源**：用户要求把整棵.local、impression-demo及同类实验资料搬到相邻独立仓库；移走后，原先失败的依赖版本检查在约0.13秒内通过。
- **原则**：会递归扫描文件系统的检查不一定遵守.gitignore。无关源码快照和实验台可在owner授权后物理移出正式项目；移动前确认跟踪范围、进程工作目录与运行引用，用同文件系统rename保留全部内容，并确认内嵌仓库HEAD和工作区状态未变。
- **边界**：归档移动不等于实验台独立运行适配、初始commit或远程备份。保留凭据文件不等于允许发布；不可把当前会话状态或正式插件当无关资料一起搬走。

## 2026-10-20 — Git执行、工具结果处理与协作等待必须分别归因

- **来源**：用户要求彻查commit/push为何卡住。真实记录显示正常commit约42秒后被根检查拒绝，成功push约4.7秒；检查递归扫描了Git已忽略的旧源码快照，且本轮重复触发。成功commit的213文件输出还触发impression同步模型摘要；工具调用总时长不等于Git进程耗时。
- **原则**：先串起hook调用链、文件选择规则和真实起止时间。明确失败不得说成命令仍卡住；已确定无关的失败及时说明授权边界，不通过重复正常提交重跑同一检查。长输出优先缩短命令输出，不把摘要模型等待算给Git；提交元数据时间不等于进程退出时间。
- **边界**：用户授权的no-verify只处理已确认无关的阻塞，相关错误仍须修复。没有进程退出计时就不伪造Git与摘要的精确分摊；本轮只解释原因，不擅改仓库级检查或Git配置。

## 2026-10-20 — 发布说明和启动确认必须绑定当前实际入口

- **来源**：用户追问为何README还要求pi-subagents；当前入口已改自带Agent但安装段未同步。提交检查又发现actor预绑定失败被吞掉、启动路径仍可能返回成功。
- **原则**：依赖与派发语义以当前入口为准，不从旧设计段落推断；actor绑定失败不得继续spawn或返回已启动。必载扩展路径指向真正入口，入口搬移保持公开export并做直接加载测试。
- **边界**：修复具体启动失败路径和文档不表示完成全部OC子代理等价；正常提交仍须遵守hook，其他会话文件与既存未推提交分别处置。

## 2026-10-15 — 同一 daemon 的不同路由响应形状各异，勿用统一 envelope 校验

- **来源**：真实 E2E 首轮两个门禁全部“不可达”：/check-permission 返回 {allowed,reason?}、/stop-check 返回 {is_terminal}，而 gate 代码统一走了 requireDaemonOk（要求 body.ok===true），形状不匹配被当成 transport 失败。单测用 fake 回 {ok:true,allowed:...} 掩盖了这一错位。
- **原则**：同一服务的每个路由响应形状必须逐路由一手核对（读 handler 返回类型或真实 curl），不能因多数路由有 ok 信封就统一套用；单测的 fake 响应形状必须来自真实响应样本，否则自己验证自己。
- **边界**：形状修复后 fail-close/soft-gate 语义不变；后续新路由接入时同样先探真实响应再写校验。

## 2026-10-15 — 失败路径与成功路径同等设计门禁；真实宿主验证用零 token 方式

- **来源**：官方 Pi 宿主 smoke 发现缺 config 的失败路径未装 not-ready gate，输入直通模型（误耗$0.026）；另发现 symlink 安装使相对导入按链接路径解析而失败。
- **原则**：插件入口在最常见的第一运行状态（配置缺失）必须与成功路径同等安全；catch 里也要安装门禁而非只 notify。真实宿主验证可用 tmux+临时项目+pi install -l，输入拦截断言以“上下文百分比不变/零模型调用”为准，零 token。扩展安装用真实路径，不用 symlink。
- **边界**：零 token smoke 不代替带 config 的成功组装验证与真实模型 E2E；意外 token 消耗必须如实披露。

## 2026-10-14 — 记录级P2在结算回合顺手钉住，不攒后续

- **来源**：fsm-3/5/6 三次对照均产生纯注释/测试补强型记录级P2；fsm-6在结算同时钉住（Step注释、cancelled分支、/models断言、重注册覆盖），零额外回合。
- **原则**：审查者明言不阻塞的注释/测试型P2，若修复成本低于记录成本，在结算同回合顺手完成，不留“后续加固”清单；行为未定义型（如/new取消语义）保留保守实现并记录即可。
- **边界**：顺手钉住不得扩大为重开对照或新审查轮次；真正需要新合同的行为变更仍走子计划。

## 2026-10-14 — 慢模型审查需匹配单工具超时与读取批量

- **来源**：fsm3实施对照两次timed-out：第一次30分钟运行上限内整读340KB patch；第二次read默认5分钟单工具硬超时被慢模型（thinking high）批量7文件读取击穿。
- **原则**：给慢模型派大材料审查时，先看中断的真实机制（运行上限vs单工具上限），同时设置 timeoutMs 与 toolTimeoutMs，并要求小批量分页读；上下文已覆盖的材料不重读。
- **边界**：同协议resume保留已读上下文；基础设施中断不当审查结论，也不因此降低审查标准或换未经授权的模型。

## 2026-10-14 — erasableSyntaxOnly 下参数属性是必现运行错误

- **来源**：fsm3实现中两次在constructor参数上写`readonly/private`修饰符，tsc/测试前的直接 node 运行立即报 ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX。
- **原则**：该仓库强制 erasableSyntaxOnly；新类一律直接写“显式字段+constructor赋值”，不写参数属性，也不要依赖类型检查提醒——提交前先跑直接 node 测试。
- **边界**：错误在实现层即时修复，不属于合同变更；不因重复小错追加审查轮次。

## 2026-10-14 — 派遣审查前先确认实际模型与额度归属

- **来源**：resume旧reviewer会话沿用了存储的codex-001/gpt-6.1-sol合同，持续消耗用户的Codex额度直到usage limit；用户本意是tmp-Haokun/glm-5.3-flash。
- **原则**：resume保留原模型合同，不继承当前期望；恢复/派遣审查前显式核实实际生效模型与计费来源，用户指定过模型时每次派遣显式传model覆盖。额度异常或模型不符时立即停并核对，不默认“配置就是这样”。
- **边界**：单次失败运行不否定已有审查结论；切换模型/过程需owner明确授权，授权后原限定范围与只读边界不变。

## 2026-10-14 — 审查运行失败与审查结论必须分离

- **来源**：D3限定确认runfc01e90c因Codex usage limit失败，持久status却仍显示requiredOutput文件存在；该文件不能证明本次给过READY。
- **原则**：先核实际run终态和结论归属；基础设施失败不等于设计否决，也不等于放行。dirty共享工作区先捕获自己变更，明确原通道恢复条件，不自行切模型/CLI/审查者或反复消耗已耗尽额度。
- **边界**：保存文件/可resume状态只是恢复依据；没有确认结果就不跨设计门，原已验证单元不因本运行故障被否定。

## 2026-10-14 — 工具映射须展开实际原生输入与语义分支

- **来源**：fsm3既定设计审查D3-1～D3-4：SDK Edit直接execute要edits数组，不能靠未运行的prepareArguments；目录ls无offset且已截断；entry时间为ISO；两份capture收尾合同不同。
- **原则**：名称相近不证明输入和语义同构。明确直接callee的原生输入，展开创建/分页/空值/单位转换等必需分支；不得从已截断视图恢复不存在的完整事实。持久格式与wire格式的转换必须显式，parent/leaf共享行为同时更新，冲突材料由原authority处理。
- **边界**：修正只承接已授权原标准；具体设计确认不冒充实现/运行成功，也不增加模型试验、审查轮次或OSsandbox要求。

## 2026-10-14 — 源码版本不是已安装二进制的能力证明

- **来源**：真实隔离FSM测试发现~/bin的server为0.10.0且缺wire_contract_version；现有target/release才实际返回0.11.0/wire2并通过通道测试。另有仓库Pi1.2.0类型与实际官方1.0.3注销API不同。
- **原则**：源码、依赖类型、实际宿主和实际可执行产物分别绑定；运行以真实capability响应判断，不因研究基线或package版本推定已安装能力。类型来源错误时固定正确依赖，不删所需逻辑迁就错接口。
- **边界**：通道通过不证明完整宿主插件运行；升级用户bin/外部仓库不由发现差异自动授权。

## 2026-10-14 — 回收发送者不等于远端控制写入已终结

- **来源**：未知identity写入反例中broker提前删除lease；progress反例中声明了回调但未保存/路由。
- **原则**：互斥释放须以拥有副作用的实际阶段为准；helper/Client死亡不能证明daemon的迟到控制PUT已结束。无确认时保留隔离并拒绝复用，不重放；通知必须有真实关联键和消费者接线，不以接口字段存在当功能成立。
- **边界**：已确认MCP发送后的关闭责任和控制POST未知分别处理；不造成功，不无限等待清理，不把测试fixture的清理顺序错误反写成业务放行。

## 2026-10-14 — 操作响应与事件义务要按真实 callee 语义判断

- **来源**：fsm-2独立设计审查D2-1/D2-2：register await后返回null仍可能没登记；on注销及事件snapshot使“注册过的handler”不同于“本轮会执行的handler”。
- **原则**：确认副作用须定位成功事实的生产者，不能从HTTP成功或await倒推出内部best-effort效果；需要时读回实际状态。事件账本分别保存未来活跃注册与当前派发快照，注销/新增不能错误改写本轮义务。
- **边界**：读回匹配仅认证该源登记，不证明完整运行或其它gate；当前snapshot的成功不代替未来epoch回执。限定修正只结算已知原合同差异。

## 2026-10-14 — 变更准入要验证接入后的结构，不只当前结构

- **来源**：首单元独立contract审查C1与实际失败回归：旧树r→c→d无环，恢复c.parent=d仍会在接入后制造c↔d。
- **原则**：结构更新的检查须包含待接入节点/边；证明旧祖先链无重复不能推出更新后无环。把待恢复self作为禁止祖先传入检查，拒绝前不改原记录。
- **边界**：局部性质测试与独立对照分别记证据；一个差异修正只结算对应合同，不自动关闭其它模块或完整兼容目标。

## 2026-10-14 — 恢复义务必须有原比较基线，并按真实角色分支

- **来源**：已授权的 workflow 设计审查 B1/B2：恢复签名只持有当前policy，无法检验原mandatory X被删；root又被统一child parent/agent检查误拒。
- **原则**：凡要求恢复时保留旧合同，必须明确保存并读取原事实基线，不能从当前配置倒推；root/child不同不变量必须有各自分支。只持久化必要非秘密事实，允许的单调增加在实际接线成功后才推进基线。
- **边界**：快照/schema只证明输入事实可比较，不证明扩展已loaded；纯准入单元和实际启动/门禁单元分别承担责任。原审查标准下的修正确认不自动放行其它单元。

## 2026-10-14 — 可静态闭合的宿主能力不得推给运行试验

- **来源**：用户指出 Stop 收尾、子身份恢复和 judge/通知机制可以直接查代码，并明确要求查。
- **原则**：先追完实际调用链和公开类型，判断机制是否存在、组合顺序及接口前置条件；源码能力未知、插件尚未编码和运行尚未验证分别记录。不能用“需要实测”掩盖尚欠的静态分析。
- **边界**：源码可实现性不等于插件已运行成功；实现仍须直接功能测试。最终目标不因调查完成而关闭。

## 2026-10-14 — 适配器按责任命名，不按被适配对象命名

- **来源**：用户纠正本次插件目录：应为 `fsm-compatible`，不是 `fsm-server`；插件不实现 FSM Server。
- **原则**：插件名称表达其拥有的功能责任。提供被适配产品的协议接口不意味着拥有该产品；兼容桥、原服务与判定权必须分别表述。
- **边界**：命名改正不证明架构或实现已兼容；外部实际二进制 `mcp-server-fsm` 等保持原名。学习记录放在本插件内，遵守本轮仅 `my-plugins/` 可写的边界。

## 2026-10-14 — 当前适配以现行契约为准，不默认继承同名旧功能

- **来源**：用户明确排除古早 `steering-flow`，要求以当前 FSM Server 与 haokun-code 行为设计。
- **原则**：相近功能名称不是复用依据；先绑定用户指定的当前产品、版本和消费接口，旧实现仅在具体契约匹配时才可能贡献。
- **边界**：排除旧基准不授权重写一切，也不把候选 subagent 重实现当已确认要求。
