# Native child 实际入口测试与修复合同

本轮来源：owner 在分层保证说明及加强测试方案后要求“测 & 修”。不修改官方 Pi、use-fsm、haokun-code 或原 OC v3 剧本，不进行新增审查或真实付费模型调用。

## 运行约束

- root 会话内冻结允许的 host agent 名单，默认仅 `general`；配置可显式替换名单，不由工具参数扩张。
- child 固定加载 fsm-compatible 及配置声明的必载扩展，不依赖父进程是否使用 `-e` 加载插件。继承 CLI 额外扩展时先规范路径并去重。
- 所有 child 由本 root 的协调器登记、鉴权和派发；递归仍使用同一份名单、必载扩展及深度上限。
- child 使用持续存在的官方 Pi RPC 会话；`agent_settled` 才表示本轮完成。停止 run 不删除 session，后续消息可以恢复。
- 子会话启动须等待插件就绪确认，未加载、初始化失败、进程退出或超时均不得返回已成功启动。
- 取消等待真实 idle/退出；只管理本协调器创建的进程。会话及协调器状态不得跨 root 共享全局变量。
- main/child 身份仍服从 FSM 的 `(root_session_id, agent_id)`；通用 host 类型 `general` 与被派发的 FSM skill 名不是同一个名字。

## 判据（先定后跑）

| 范围 | 通过条件 |
| --- | --- |
| -e 与项目安装 | 两种真实 root 启动方式都能创建带插件及门禁的 child |
| 名单 | 合法名字启动；非法名字在 spawn 和 actor acquire 之前拒绝 |
| 递归 | parent→child→grandchild 身份独立；到深度上限拒绝；不能通过参数删除扩展或换名单 |
| 握手 | 必载扩展缺失/失败或 child 启动失败，调用失败且无遗留进程 |
| 生命周期 | 启动、settled、异常退出、停止、再次发送消息的状态与报告真实对应 |
| OC/Pi 对照 | 同一 FSM/输入下，比对工具允许拒绝、状态、派发/回执及文件副作用；ID/根路径归一，不比较模型措辞 |
| 已知缺口 | B62 等两端都允许的行为记为一致但无保护，不伪称安全保证 |
| 完整交付 | 原 v3 不改；另建按真实状态图合法进入 V_DELIVER 并退出的场景，明确走 verified 还是 failed 分支 |

## 测试方法

实际宿主、FSM daemon、工具和文件系统执行；只有模型输出通过本地 mock 提供。每个运行独立工作区、data-dir、端口及会话目录，保存源码身份与脱敏 trace。不以孤立内部类调用代替入口测试，不因失败修改判据。

真实模型自主执行能力另行授权模型与预算，不包含在本轮确定性测试中。若合法交付需要当前环境没有的真实验收材料，应明确阻塞，不关闭 gate 或伪造证明。
