- Correct: the managed and native snapshot acquisitions are single-owner. `CoordinatedSnapshot.execute()` rejects a concurrent request while its abort controller is present (`coordinated-snapshot.ts:9-23`); `RuntimeSnapshotOwner.begin()` rejects while active and clears ownership both on release and setup failure (`runtime-snapshot-owner.ts:20-48`); native acquisition refuses stopped/incompatible/already-owned TUI internals and rolls back temporary `doRender`/`stop` properties after partial installation failure (`native-snapshot-target.ts:15-19,32-53`). The partial-install test passes at `native-tui-snapshot.test.ts:59-71`.
- Correct: once a lease is acquired, the normal snapshot body releases it in `finally`, including state/capture/render failures; a release error is retained as the snapshot failure when there is no earlier failure (`execute-snapshot.ts:35-60`). Artifact publication occurs only after release (`execute-snapshot.ts:61-79`). Tests prove restoration after before-capture, after-capture, artifact, and native-capture failures (`tui-snapshot.test.ts:116-162`, `native-tui-snapshot.test.ts:73-89`).
- Correct: coordinator lifecycle cancellation is abort-driven. Session replacement, run completion, and shutdown call `CoordinatedSnapshot.cancel()` (`runtime-coordinator.ts:23-24,126-127,147-148`); the abort listener cancels the lease and the aborted transaction returns without publishing (`execute-snapshot.ts:24-25,57-62`). `snapshot-lifecycle.test.ts:18-38` proves shutdown restores `terminal.write`, drops blocked bytes, returns `undefined`, and reaches `disposed`.
- Correct: lease completion is idempotent and restores `terminal.write` before replay/drop. Replay exceptions still execute the owner release callback (`snapshot-lease.ts:20-33`). Direct stop cancels the lease before native recovery/original stop (`runtime-patch.ts:113-127`, `native-snapshot-target.ts:28-31`); `snapshot-lifecycle.test.ts:40-63` proves blocked bytes are not replayed after stop.
- Correct: blocked-output accounting uses byte length and allows at most exactly 64 MiB. A write that would make the total exceed the cap records `blocked-output-limit`, drops the retained blocked writes, releases ownership with forced catch-up, then forwards the crossing write (`snapshot-lease.ts:5,35-52`). This path is source-proven but has no focused cap-crossing regression test.
- Correct: child processes have explicit abort and timeout inputs. `ps` receives the signal and timeout (`resolve-controlling-tty.ts:15-19`); `osascript` receives the signal, a 5-second default timeout, and a 64 MiB `maxBuffer` (`terminal-app-capture.ts:7-8,30-40`). Hung-child tests pass for both commands (`resolve-controlling-tty.test.ts:15-34`, `terminal-app-capture.test.ts:8-22`).
- Correct: artifact files use exclusive, no-follow opens, mode `0600`, per-file `sync()`, and handle closure in `finally`; directories use no-follow opens, mode `0700`, directory validation, and closure (`snapshot-artifacts.ts:17-50`). Publication ordering is artifact writes/sync, snapshot-directory sync, temporary-pointer write/sync, pointer rename, then root-directory sync (`snapshot-artifacts.ts:89-116`). Exact bytes, permissions, `latest.json` replacement, artifact symlink collision, and victim preservation pass at `snapshot-artifacts.test.ts:28-72`.

- Blocker: pre-publication cleanup can recursively delete a colliding snapshot directory that this invocation did not create. `writeSnapshotArtifacts()` derives a deterministic `sessionId/timestamp` directory, enters the publication `try`, and on every failure before `latest.json` rename executes recursive removal while `published` is false (`snapshot-artifacts.ts:89-116`). If the timestamp directory already exists, or an exclusive artifact open reports `EEXIST`, cleanup targets that pre-existing directory rather than only files created by this transaction. The symlink/collision test reaches the `EEXIST` path (`snapshot-artifacts.test.ts:62-68`) but only proves the external victim is unchanged; it does not prove preservation of all pre-existing contents in the colliding snapshot directory. Add a regression that seeds an existing timestamp directory with an unrelated sentinel, expects rejection, and asserts the directory and sentinel remain byte-identical.

- Blocker: session validation accepts the path segments `.` and `..`. The validator permits every non-empty string matching `/^[A-Za-z0-9._-]+$/`, then passes the value to `join(root, sessionId)` (`snapshot-artifacts.ts:89-98`). Consequently `sessionId: ".."` places the timestamp directory outside `.pi/snapshots`, and `sessionId: "."` collapses the session level. Production obtains this value from `ctx.sessionManager.getSessionId()` (`codex-viewport.ts:22-41`), but no checked contract guarantees that external value cannot be a dot segment. Add direct tests for `"."`, `".."`, and empty IDs and require rejection before any filesystem mutation.

- Note: direct `TUI.stop()` cancels only the lease, not the coordinated transaction. The stop paths call `snapshotOwner.cancel()`/`lease.cancel()` (`runtime-patch.ts:113-117`, `native-snapshot-target.ts:28-31`), whereas only coordinator lifecycle methods abort `executeSnapshot`. After a delayed physical capture resolves, execution continues to state capture, fails diagnostic rendering because the lease is released, and can still invoke `writeArtifacts` because the signal is not aborted (`execute-snapshot.ts:44-62,63-79`). `snapshot-lifecycle.test.ts:40-63` reaches this path but does not assert the snapshot result or artifact-writer call count. This permits post-stop filesystem publication and access to stopped TUI state. Add a test asserting direct stop resolves the command as `undefined` and never calls `writeArtifacts`, or explicitly specify failed-artifact publication after stop if it is intended.

- Note: cap coverage is incomplete. Blocked ordinary writes and `osascript` stdout are each capped at 64 MiB, but diagnostic `terminalOutput` grows without a bound, every output accessor performs `join("")`, snapshot states are unbounded objects, and artifact JSON/text serialization is fully buffered (`snapshot-lease.ts:35-65`, `snapshot-artifacts.ts:52-87`). A renderer producing a very large diagnostic frame can therefore exceed the nominal resource cap and create additional full-size string/Buffer copies. No focused test crosses either 64 MiB boundary or exercises an oversized diagnostic/state payload.

- Note: publication has a committed-but-reported-failed state. `latest.json` is renamed before `syncDirectory(root)` and `published` is set immediately after rename (`snapshot-artifacts.ts:108-115`). If the final root sync fails, the function rejects and `executeSnapshot()` returns `undefined`, while the new directory and visible `latest.json` remain. Conversely, rename failure leaves the old pointer in place and cleans the unpublished directory. These branches are source-reachable filesystem errors but are not fault-injected by current tests.

- Note: `CoordinatedSnapshot.cancel()` clears its single-flight guard before the cancelled async capture settles (`coordinated-snapshot.ts:24-29`). A replacement request may acquire and immediately release another lease while the shared `SnapshotJournal` is still active; `journal.begin()` then fails and the replacement returns `undefined` (`execute-snapshot.ts:22-38,53-62`, `snapshot-journal.ts:7-25`). This is resource-safe but makes cancellation completion nondeterministic and can reject the first post-cancel snapshot until the old capture honors abort.

## Partial external boundaries

- `execFile` timeout/abort behavior, signal handling, and descendant termination are delegated to Node and the operating system. Tests prove prompt rejection for shell scripts that `exec sleep 60`, not absence of all surviving descendants.
- With no explicit TTY, `captureTerminalApp()` gives `ps` and `osascript` separate full timeout budgets, so the total operation can approach twice `SNAPSHOT_PROCESS_TIMEOUT_MS` (`terminal-app-capture.ts:30-39`). No end-to-end deadline test covers both children.
- Terminal.app JXA tab enumeration, returned history size/semantics, and Apple permission/error behavior are external. Tests cover timeout and payload validation, not a real Terminal.app process.
- `O_NOFOLLOW` protects the final opened path component. The trustworthiness of `cwd` and parent components such as `.pi` remains external; a symlinked parent is not independently opened component-by-component.
- Rename atomicity and directory-sync durability are filesystem guarantees. Current tests use the host temporary filesystem and do not inject `write`, file `sync`, directory `sync`, close, rename, or cleanup failures.
- Cross-process publication is not coordinated. The in-memory single-flight guard covers one coordinator only; deterministic snapshot and temporary-pointer names can collide across processes.
- The physical capture cap applies to child stdout, not total live memory after JSON parse and duplication into artifact objects.

## Optimization

- Track `directoryCreatedByThisCall` and only recursively remove that directory when true; never remove a pre-existing collision target. Prefer a random transaction directory/temp pointer created with exclusive semantics, then rename the completed directory into its final timestamp name.
- Reject `sessionId === "." || sessionId === ".."`; preferably validate one canonical path segment and verify `relative(root, sessionDirectory)` neither escapes nor equals the root.
- Give the snapshot owner a transaction-cancel callback so direct stop aborts capture and suppresses publication, rather than merely releasing terminal ownership.
- Keep the coordinator single-flight token until the cancelled execution’s `finally` completes, or associate each execution with its own journal instead of sharing one mutable journal.
- Apply a single deadline across TTY resolution and Terminal.app capture, forwarding only the remaining budget to each child.
- Cap or stream diagnostic output and artifact serialization. At minimum, test exact-limit acceptance, one-byte-over crossing, multibyte UTF-8 accounting, oversized diagnostic output, and replay/write failure.
- Inject a narrow filesystem operations interface for tests. Exercise exclusive-open collision, partial file install, file-sync failure, snapshot-directory-sync failure, temporary-pointer collision, rename failure, root-sync failure, close failure, and cleanup failure without changing production ordering.
