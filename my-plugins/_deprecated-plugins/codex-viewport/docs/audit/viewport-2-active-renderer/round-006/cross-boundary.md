# Round 006 clean-room cross-boundary/spec audit

## Review

- **Blocker — renderer ownership is released at the wrong official lifecycle boundary.** The extension maps every `agent_end` directly to `runtime.finishRun()` (`my-plugins/codex-viewport/codex-viewport.ts:77-79`). Official Pi keeps `_isAgentRunActive` true after `agent.prompt()` and runs `_handlePostAgentRun()`/`agent.continue()` in a loop before settling (`packages/coding-agent/src/core/agent-session.ts:1044-1055`); only `_emitAgentSettled()` clears the active flag and emits `agent_settled` (`packages/coding-agent/src/core/agent-session.ts:564-571`). Reachability: an agent invocation emits `agent_end` → the plugin enters drain/native handoff → Pi finds a follow-up or continuation and calls `agent.continue()` while the same session run remains active. This violates the specification that native/static ownership is the idle boundary and can introduce a native handoff/re-entry (and visible redraw) between continuation turns. The non-decisional fix is to align ownership completion with `agent_settled`; repeated per-invocation `agent_start` events inside one active run must be idempotent rather than tearing down the existing managed epoch.

- **Correct — DSR has one explicit runtime owner and stale entry work cannot activate.** `RuntimeCoordinator` owns one instance-local `TerminalCursorQueryOwner`, cancels it on capture/shutdown/supersession, and combines generation plus patch-identity checks before activation (`my-plugins/codex-viewport/runtime-coordinator.ts`, entry/recapture paths). Each entry calls `cursorQueryOwner.begin()` (`my-plugins/codex-viewport/managed-entry.ts:29-39`; `my-plugins/codex-viewport/width-reentry.ts:28-38`), and `queryTerminalCursor` filters only the DSR report while replaying adjacent input (`my-plugins/codex-viewport/query-terminal-cursor.ts`). Reachability tests include split reports, adjacent user input, cancellation replay, late timeout reports, removal before a subsequent query, and write-failure ownership abort (`my-plugins/codex-viewport/query-terminal-cursor.test.ts`). No second DSR consumer was found in the 56-file implementation.

- **Correct — frame diff and cursor placement preserve the active-renderer boundary.** The viewport frame requires exact area height and a cursor within width/height (`my-plugins/codex-viewport/inline-viewport-frame.ts:16-28`). The ordinary diff uses absolute CUP plus `EL 2`, clears rows relinquished only at the prior bottom, and contains no CR/LF scrolling (`my-plugins/codex-viewport/screen-frame-diff.ts:3-31`). Cursor placement offsets the logical cursor by `area.top` (`my-plugins/codex-viewport/cursor-placement.ts:4-10`). `ManagedRenderer.render()` prepares state, computes history/frame/cursor bytes, performs one terminal write, and accepts ledger/frame/stable-row state only after that write succeeds (`my-plugins/codex-viewport/managed-renderer.ts`, `render`, `prepareCommit`, and `acceptPrepared`). This matches official Pi’s cursor marker model and logical-versus-hardware cursor bookkeeping (`packages/tui/src/tui.ts`, `extractCursorPosition` and renderer state).

- **Correct — native handoff is conservative and exact.** `prepareNativeHandoff` rejects incomplete stable-row attestation, surviving displaced entry rows, terminal images, absent cursors, unequal visible bytes, or unequal cursor coordinates before priming Pi’s cached renderer fields (`my-plugins/codex-viewport/native-handoff.ts`). `commitNatively` invokes exactly one saved native `doRender` only after this preparation (`my-plugins/codex-viewport/native-commit.ts:11-27`); mismatch and throw paths return to synchronous native recovery/fencing through `InstalledRuntimePatch` (`my-plugins/codex-viewport/runtime-patch.ts`). Official Pi owns the same `previousLines`, dimensions, viewport, logical cursor, hardware cursor, kitty IDs, and maximum-rendered-line fields (`packages/tui/src/tui.ts`, `TUI`). The two handoff regression cases pass (`my-plugins/codex-viewport/native-handoff.test.ts`).

- **Correct — AI-visible data and session-owned runtime state remain isolated in the inspected paths.** Event handlers observe assistant/tool lifecycle IDs but do not replace message payloads, provider data, tool arguments/results, abort behavior, or persistence (`my-plugins/codex-viewport/codex-viewport.ts:51-83`). Renderer, reconciler, ledger, snapshot owner, and DSR owner are instance fields rather than module globals (`my-plugins/codex-viewport/runtime-coordinator.ts`; `my-plugins/codex-viewport/runtime-patch.ts`; `my-plugins/codex-viewport/component-ledger-reconciler.ts`; `my-plugins/codex-viewport/transcript-ledger.ts`). Official `AgentSession` owns its extension runner, queues, abort state, session manager, and cleanup per instance (`packages/coding-agent/src/core/agent-session.ts`). The isolation regression observes lifecycle events without mutating payloads or aborting (`my-plugins/codex-viewport/runtime-event-isolation.test.ts`). No cross-session mutable module state was found.

- **Note — terminal admission is an unresolved capability-policy choice, not a proved capability contract.** Admission is inferred from `TMUX`, four `TERM_PROGRAM` names, or broad `TERM` prefixes including `vt100` and `ansi` (`my-plugins/codex-viewport/detect-supported-terminal.ts:3-8`). Every managed transaction unconditionally emits synchronized-update mode 2026 (`my-plugins/codex-viewport/terminal-render-plan.ts:7-10`), and the expansion grammar additionally uses DECSTBM, CUP, CR/LF, and scroll-region reset (`my-plugins/codex-viewport/viewport-expansion.ts:14`). Official Pi also emits synchronized-update markers and cursor/erase grammar without negotiation (`packages/tui/src/tui.ts`, `doRender`; `packages/tui/src/terminal.ts`, `ProcessTerminal.write`), but that proves compatibility with Pi’s assumptions, not atomic-update support on every plugin-allowed terminal. The current specification itself says the terminal matrix is incomplete (`my-plugins/codex-viewport/docs/design/proofs/scco-composition.md:3`). Decision required: either (a) define these sequences as best-effort and accept tearing where mode 2026 is ignored, (b) narrow admission to a tested matrix, or (c) add a capability query/probe. Recommendation: narrow to a tested matrix until probing and direct IME/terminal evidence exist.

- **Note — live overflow remains an explicit product/design gate.** Current implementation grows only into bottom slack and then crops the pending live prefix: `planLiveRegionGrowth` leaves `top` unchanged and calls `buildViewportExpansion(area.top, area.top)`, so expansion is always zero (`my-plugins/codex-viewport/live-region-growth.ts:10-20`). The architecture records upward expansion versus cropping as the unresolved Round 005 D-layer gate (`my-plugins/codex-viewport/docs/design/architecture.md:56`), while detailed design’s module table still says “upward-on-overflow” (`my-plugins/codex-viewport/docs/design/detailed-design.md:15`) even though its behavior section correctly says downward-only plus crop (`my-plugins/codex-viewport/docs/design/detailed-design.md:77`). Decision required: preserve fixed stable rows and crop pending display, or scroll attested stable rows upward to expose more pending content. Recommendation: retain cropping unless a new physical-history proof and terminal matrix justify scroll-region mutation.
