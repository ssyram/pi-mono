# AI 学习原则

## 2026-11-24 — 全局软链插件不能直接接入未经加载验证的半成品

- **来源**：Profiles发现实现写出readonly unknown的语法错误，并被全局extensions软链立即加载，导致原Profiles启动失败；同时用户原问题经tmux复现为在线目录刷新与具名实例静态目录脱节，不是zai/Coding类型选择错误。
- **原则**：全局软链使工作树代码等于实际运行代码，先在未接线模块和隔离安装版loader验证，再启用入口；不能把新引入的回归混为旧故障。原功能受影响时精准撤回本轮接线、保留工件并验证原加载，而不是继续功能开发。
- **边界**：pi update --models输出成功不证明目标profile目录已变化；直接槽无凭据可能被跳过。官方已有模型应优先调查目录继承，不为已解决的发现问题继续扩建插件。暂停恢复不等于用户授权取消全部目标。

## 2026-11-24 — 权宜覆盖范围与最高正确性原则分开维护

- **来源**：用户明确选择仅在 provider-profiles 增加正交自动发现能力，并要求警告非Profiles不能使用；同时要求Principles照旧。
- **原则**：覆盖对象可以由用户明确收窄，但不能借此放宽凭据隔离、官方优先、缓存回退、thinking/context正确性或真实验收。新增专项归属实际创建者目录，旧身份职责中的目录禁令要记录精确例外，不让新旧文档同时声称互斥规则。
- **边界**：仅添加文档不算功能完成；README必须标明规划中，不把支持Profiles误报为所有来源已有自动发现。

## 2026-11-24 — 事后接管失败不能推出必须改核心

- **来源**：用户指出新 provider 本来就由插件创建，应该在发现/创建 provider 时获取模型。核实 provider-profiles 异步 factory 和 add-login 均在注册前调用 instanceProvider；现 getModels 仅取静态来源且不带 refreshModels。
- **原则**：先区分 provider 创建者组合能力与第三方事后接管；后者时序失败不否定前者。先查自有插件的最小创建入口，不把“完全不改其他插件”的局部设计限制偷换成“纯插件不可能”。
- **边界**：创建入口存在只证明有组合时机，不证明零改其他插件已可接入，也不替代失败路径、刷新和真实验收。撤回必须修改 Pi 核心的过强结论。

## 2026-11-24 — 机制试验必须在超时前交回可续接证据

- **来源**：GLM mechanism 在 30 分钟后超时；仅留下试验脚本和一句关于异步落盘的推测，没有完整机制结论，后续设计/实现未启动。
- **原则**：机制探索须有更小的完成单元、运行预算和超时前检查点，先交已运行命令、退出码与未闭合条件；不得用持续调试消耗整轮而无证据交接。失败后保留工件、停止后继，不把猜测升级为根因。
- **边界**：共享 cwd 的 changed-files 摘要不证明修改来自该子任务；归因须查实际调用，绝不据摘要回滚其他会话文件。超时不证明设计不可行，也不允许宣称已通过。

## 2026-11-24 — 用户真实使用与失败非干扰必须分别证明

- **来源**：用户明确最终要亲眼看到 GLM-5.4 无痕发现并正常使用，同时要求逐返回/失败路径代码论证回到原始官方行为，失败残留不影响官方能力。
- **原则**：mock/faux 是实现证据，不得替代用户实用验收；每个退出点、异步失败、取消和迟到结果均需对应状态、副作用、恢复与残留隔离依据。不能用 catch、测试绿或 agent 自述取代代码论证。
- **边界**：回退不授权偷偷换模型、吞官方错误或重发付费请求；用户未亲验只标记待实用验收，不能先宣布可正常使用。

## 2026-11-24 — 缓存被重读不等于接入刷新生命周期

- **来源**：用户要求每次 model refresh 自动发现并回收官方已接管的补充；原蓝图却只在 session_start/turn_start 运行，并用 models.json 会被重读证明需求已满足。
- **原则**：分别证明缓存恢复、每次刷新归并、后台网络更新和首次模型解析的实际调用顺序。没有事件不等于没有 provider 生命周期入口，不能只凭方法名或配置文件被读取就声称链路完成。
- **边界**：缓存先返回允许后台网络滞后，不自动授权官方接管清理也等到下一轮 TTL；无缓存、刚发布模型、零等待无法同时保证。

## 2026-11-24 — 目录缓存不是当前官方基线，实例名不是来源名

- **来源**：源码要求 overlay 新于 bundled generation 才生效；OpenRouter 使用个性化替换；Pi 的 zai 指向 Coding 端点，而外部同名目录指向普通 API，glm-5.4 在另一个 Coding 目录。
- **原则**：按当前实例的端点、套餐、模型类型和真实 ID 建立来源关系，按实际生效目录判定官方接管。不要直接并起静态目录和原始缓存，也不把 canonical 模型谱系当成价格、权限或传输兼容性的证明。
- **边界**：checkedAt/TTL 控制再请求时机，不决定缓存模型是否生效；未知官方状态不能解释成官方为空。

## 2026-11-24 — 原子文件替换不能证明不丢数据或所有权安全

- **来源**：原蓝图以 temp+rename/备份解释多会话安全和自愈，但可覆盖用户并发编辑；models.json 与 sidecar 分开提交还存在中断窗口。现有 provider-profiles 会拒绝同名 models 字段。
- **原则**：先核全部实际配置消费者，再决定持久化位置。分别证明文件完整性、并发提交、登记一致性和用户修改后的所有权移交；不能用“下轮自愈”解释无法从上游重建的用户输入。
- **边界**：不以修另一个插件或放宽它的冲突检查作为当前插件可行性的隐含前提；目录注册的可选持久化不能被误报为必然同槽冲突。

## 2026-11-24 — 调研配置必须脱敏，独立意见必须落回一手证据

- **来源**：前期调研打印了可能含密钥的 provider 配置；本轮独立报告又把旧文档中的“实测”表述当成一手事实，并误判 provider 持久化为必选。
- **原则**：优先读配置结构和源码；必要时只取非敏感字段，绝不整份打印配置。独立报告是分析材料，事实仍回到源码或原始请求/响应；未执行的原生调用不能写成实测。
- **边界**：本轮没有读取真实凭据、调用付费 provider 或改动代码；独立检查一致不等于生产可用证明。
