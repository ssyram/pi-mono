# model-scout — 最高原则

状态：用户于本轮明确确认；Q.I 的权威来源是用户对上一轮最终行为合同的确认，不是旧蓝图的自述。

## Q.I：最终行为合同

Q1 装上就工作：识别已有账号及实际套餐，不重新配置账号、不改变凭据。
Q2 每次 Pi 模型刷新都参与：先提供缓存版补充，网络发现在后台进行，不要求额外命令。
Q3 官方永远优先：按当前实例真正生效的官方目录判定，不重复、不覆盖官方参数，官方接管后补充自动退出。
Q4 不动用户配置：不将发现结果写入 models.json，不修改 provider-profiles；只维护插件自己的缓存。禁用后补充退出，原模型和账号不受影响。
Q5 可选意味着可用：区分套餐、模型用途和调用方式；没有依据的上下文、价格、思考能力不捏造。不把未经支持的 operation 当成聊天模型。
Q6 失败不破坏原功能：断网、限流、缓存损坏、多 Pi 并发、关闭或重载都不能损坏原账号、用户配置和官方模型；更新失败保留最后有效结果。
Q7 代码级回退论证：每条返回路径、每条失败路径都必须严格说明如何回到原始官方行为；任何失败残留不得影响用户使用官方能力。以实际代码路径、状态与副作用论证，不以 catch、测试绿或 agent 自述替代。
Q8 最终端到端验收由用户亲验：用户亲眼看到 GLM-5.4 被无痕自动发现并正常使用。mock/faux、目录出现、单条HTTP成功都不能代替这一验收。具体执行和证据要求见 acceptance.md。

## Q.A：事实与未闭合前提

- 已有公开 provider 注册与 refreshModels 生命周期接口，模型读取与网络刷新可分离；入口存在不等于本插件端到端已成立。
- 既有 provider-profiles 使用 native Provider 实例，不能直接用 legacy 配置覆盖而丢掉原鉴权。
- 模型源名称与 Pi 实例名称不等价，必须按实际来源、端点和套餐关联。
- models.dev 是元数据/候选来源之一，没有保证永远比官方 Pi 或 provider 官网更新快。
- 首装完全无缓存时，不能同时保证零等待与立即获得刚上线模型；先保留官方可用模型，发现结果后台补齐。

## Q.E：本任务已有教训

旧方案把“缓存文件被重读”当成刷新接入，把原始官方缓存当成生效目录，并直接写用户配置；已被 docs/_finegrained_report.md 的源码反例否定。独立意见和接口名称不替代实际机制证据。
