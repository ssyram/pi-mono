# 候选外部接口义务：注册完成后的统一目录装配

状态：待用户授权，不是已确认架构或已实现 API。仅本插件文档，不修改 Pi 核心、其他插件或真实安装。

## 原始目标

对官方 Provider、Profiles 和其他已注册 Provider 统一发现缺失模型；首次恢复用缓存，联网后台更新；官方优先；不破坏原账号/传输；残留不影响官方使用。最高合同仍为 principles.md 和 acceptance.md。

## 已找到的位置

packages/coding-agent/src/core/agent-session-services.ts 在全部配置型/native/virtual注册完成后，于 :194 执行 modelRuntime.refresh({allowNetwork:false})。统一处理应在首次模型解析之前完成缓存装配；以后目录刷新同样需执行官方优先归并。源码依据和公开接口缺口见 unified-refresh-findings.md。

## 最小能力需求（不是确定接口签名）

1. 在所有启动期注册完成、首次 cache-only refresh/模型解析之前，允许扩展读取该会话最终注册的 Provider，包含官方与具名实例。
2. 允许会话拥有的目录装配层保留原 Provider 行为，只补充目录和发现刷新；不靠覆盖原账号注册、重写用户配置或恢复后setModel。
3. 装配只属于当前会话。禁用/reload/异常卸载后原 Provider 继续可用；不得把插件目录写入官方模型缓存。
4. 每次刷新用当时实际官方基线去重；不能只依靠一次启动通知。已有 refreshModels 可否安全组合，须在具体接口方案中证明，不能以新增一个事件代替完整论证。

## 必须保留的宿主语义

原账号身份、认证、端点、headers、transport、filterModels、官方模型对象/参数、官方错误与请求次数不变。插件回调异常不得中断原生刷新；异常不能以吞官方错误的方式处理。插件异步工作必须有会话/代次所有权，取消和迟到完成不得发布。

一个“注册完成”事件只解决可见性与时机，不自行证明上述恢复与非干扰成立。不能在这里预先承诺添加事件即全部完成。

## 授权边界

用户尚未授权修改 Pi 官方源文件。当前只请求允许研究并实施最小通用扩展接口，而非把模型发现逻辑放入核心；发现、缓存、各来源适配和用户验收仍属于 model-scout 插件。

若授权，应先按 Pi 扩展文档与现有实现完成具体签名、生命周期、逐路径回退、关闭恢复和独立设计检查，经过用户要求的原合同后再编码。若不授权，不将现有未证明的事后包装/虚拟桥接工件交付成品，也不继续反复尝试同一路线。

是否确实排除了所有纯插件技巧，不在本文件结论之内。当前请求来自已定位、尚未有公开接线的具体能力缺口，不是数学上的不可能性证明。
