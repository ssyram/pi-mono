# model-scout — 最终验收与回退证明合同

权威：用户本轮明确要求，承接 principles.md Q7/Q8。实现、设计检查和实现对照均按本标准判断。本文不自行扩大到修改核心、其他插件、真实配置或自动消费付费请求。

## 1. 用户验收

最终由用户本人看到：正常加载插件后，不运行扫描/确认/导入等额外命令，正常刷新和选择模型即可使用新发现的真实 GLM-5.4；原账号、原模型和原有使用流程正常。

原始用户判据：
- “端到端验收很简单，我这边起码能够正常用。”
- “严格论证每一条返回路径、每一条失败路径，都会 fallback 成最后的原始行为，不会影响我的行为。”
- “任何的失败残留都不会影响到我对官方那个东西的使用。这个东西一定要通过代码论证好。”
- “我要亲自看到 GLM 5.4 能够被发掘，能够被无痕的发掘使用。”

本地 mock/faux 用于覆盖边界与接线，但不能记录成最终通过。用户未亲验前，交付状态只能是“准备好供用户实用验收”，不能是“用户已可正常使用/验收通过”。

真实验收的正常使用路径包括宿主现有工具/历史处理，不把只能返回一句文本的特殊调用伪装成完整支持。不得通过偷偷切到其他模型取得成功。

最终使用 tmux 启动真实 Pi，按用户正常流程打开 /model，确认 GLM-5.4 自动出现、可选择并实际使用；不在当前机制探索阶段启动用户的真实验收会话。

用户补充的真实 TUI 验收：
- 模拟 Shift+Tab，逐次检查 GLM-5.4 实际支持的 thinking levels 能正常循环切换；界面档位与当前模型状态一致，不暴露模型不支持的档位，不只改显示文案。
- 核实这些档位映射到实际请求参数符合该端点/套餐的支持规则；不能把“按键使文字变化”当成有效思考档位支持。
- 选择模型后及首次响应后，检查 context length 显示均与该模型及实际套餐的可信元数据一致；不得使用猜测默认值，虚拟入口与桥接物理模型不得在首个响应后把正确长度覆盖成另一数值。
- 正常重启/恢复后继续验证模型选择、thinking levels 与 context length；确认原官方模型仍可用。

以上交付真实操作记录与结果；模拟源和 faux 调用仍只属于实现证据，不能替代最终亲验。

## 2. 原始行为基准

基准是同一 Pi 版本、同一会话配置/账号/凭据和原 provider 下，不安装本插件时官方功能的可观察行为；不是作者重新构造的近似 provider。

必须保持：身份、认证、端点、请求头、原模型及其参数、官方可用性策略、请求/工具历史传输、官方刷新及错误语义。不得以“回退”名义吞掉官方错误、擅自重发付费请求或换模型。

插件发现的新 ID 在无插件时本来不属于官方目录，不能靠声称“自动换一个原有模型”来证明等价；新增调用能力必须单独证明。回退首先保证原有官方路径与配置不被插件故障污染。

## 3. 每条代码路径的证明格式

在详细设计中先列状态和不变量；实现后建立 failure-paths.md，逐实际函数、分支与退出点对照代码，不仅抽样主路径。每行至少包含：

| 函数与代码位置 | 路径/退出条件 | 已成立前提 | 已发生副作用 | 返回/异常语义 | 回退动作及其失败情况 | 残留状态/所有者 | 官方行为不受影响的代码依据 |
|---|---|---|---|---|---|---|---|

每个正常 return、提前 return、throw、catch、await rejection、取消与迟到完成都必须有归属。调用别的模块时引用真实 callee 契约；循环给有限性依据。不得使用“应该没事”“有 try/catch”“下一轮自愈”替代推导。

高风险点必须具体覆盖：
- 注册前失败、注册中断、原 provider 恢复失败、重复包装和加载顺序。
- 首次缓存恢复、无缓存/坏缓存/旧schema、304缺体、源响应部分成功和元数据校验失败。
- 超时、401/429、断网、离线、abort、refresh supersede、会话关闭及reload后的旧任务提交。
- 缓存写权限失败、原子替换中断、多进程竞争、写完但尚未发布、持久残留再次启动被读取。
- 官方接管与插件清理失败；禁用/卸载后的独立缓存不能被官方目录层采用。
- 日志、错误输出和缓存不得泄漏凭据；调试输出本身不应破坏官方功能。

不变量：官方状态不由插件发现流程改写；插件私有残留只能被仍有效的插件所有者读取，不能进入官方缓存槽；过时代次不允许发布；回退不依赖坏缓存或失败的网络源。若某条路径无法证明，则是未满足合同，不是已接受的风险。

## 4. 证明与运行证据的分工

代码论证负责解释所有已设计返回/失败路径为何保持原始官方行为；直接故障注入测试负责为具体实现提供反例检查，两者不能互相替代。独立 reasoner 按本文件固定标准一次对照实际代码，不由实现者自评通过。

不得宣称插件能保证宿主进程被杀、磁盘硬件损坏或不可恢复 OOM 后继续运行；这些属于执行环境前提。执行环境边界必须显式记录，不能借此前提排除插件正常产生的异步错误、取消、残留或注册恢复失败。

## 5. 实施和交付顺序

1. 机制试验证明不破坏原 provider、profiles 与启动/刷新时序；不可行则先报阻塞。
2. 主会话完成详细设计、原始验收 expectations 和路径证明义务；独立设计检查后再实现。
3. GLM 实现与直接测试，并提供逐路径代码映射；主会话监督并收取独立契约结论。
4. 给用户可实际加载的插件及正常使用入口，安排真实 GLM-5.4 亲验；不自动改用户安装或凭据，不把后台启动记成通过。

最小最终交付：插件、必要文档、代码路径回退论证、直接测试结果、用户实用验收的当前状态。若真实模型暂不可用或源尚未适配，明确未完成；不回退成只能展示模型的demo。
