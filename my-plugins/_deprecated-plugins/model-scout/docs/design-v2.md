# model-scout v2 — 架构与实施约束

状态：取代旧 architecture.md 的路线；受 principles.md 约束。刷新接入方式必须先通过下述机制门，不能把待证设计写成已实现。

## 1. 作用域与实际流程

仅开发本插件，不改 Pi 核心、provider-profiles、用户 models.json、凭据或现有安装。运行时补充层保留原 provider 的身份、鉴权、请求头、端点、传输和官方刷新行为；插件独立缓存，不向官方 models-store 写自己的目录。

每次缓存阶段：取得原 provider 当前官方列表 O；取得插件最后有效且与本实例/端点/套餐匹配的补充缓存 C；发布 O 加上 C 中不与 O 同类型同 ID 重复的模型。每次网络阶段：允许联网且源过期时后台获取候选，校验后替换插件缓存；下一次读取/刷新使用新快照。官方接管判定不受外部源 TTL 控制。

后台任务完成只发布到仍有效的会话/注册代次；关闭、reload、改配置后的旧任务不能提交。禁用插件不得留下可被误当作官方的模型快照。

## 2. 模块与契约 P

- composition：唯一补充入口；输入官方当前模型及可信补充，输出合并列表。P1 官方模型对象不修改；P2 身份为实例+operation+线上 ID；P3 去重只剔除插件条目。
- integration：对接宿主公开注册/刷新生命周期。P4 保留原 provider 所有行为；P5 每次宿主刷新参与；P6 缓存恢复赶在首次模型解析前；P7 不递归调用刷新、不抢占其他插件注册。具体接线须经机制试验和主会话确认。
- source-policy：从实际实例来源、端点、套餐选择发现适配器，不把 profile 名字当源 ID，不擅改 baseUrl。P8 同源同套餐可复用元数据；跨服务价格/权限不继承。
- discovery：官方结构化目录/profile 为发现依据，社区目录可辅助补元数据。P9 列表认证/分页/operation 按具体协议定义；P10 tool/thinking/compat/API 规则没有依据则保留为候选，不伪装支持。
- cache：只读写插件目录。P11 last-good 快照+条件请求；304 必须有可用正文；坏响应不覆盖旧快照。P12 来源级 freshness、重试条件与成功时间分离；换账号/端点不能误用权限缓存；不把 key 存盘。
- lifecycle：会话所有权的 single-flight、取消和代次；多进程只共享可序列化快照，原子发布且不会写坏其他进程缓存；失败不影响官方模型。

每个模块一个概念；index.ts 只 re-export。源文件不超过 200 非空非注释行；不建 utils/helpers 杂物文件。不得为了行数引入无用途的一行包装。

## 3. 核心结构与不变量

InstanceSource：实例 ID、受信来源 ID、端点、套餐、operation；仅用于路由和缓存归属，凭据从宿主解析，不进入快照。
Snapshot：版本、来源标识、验证通过的模型、检查时间、可选 validator；内容不可包含 apiKey/认证头。读取失败是明确的 cache-miss，不冒充有效空目录。
RefreshState：idle 或 running（controller、generation、pending promise）；所有者为会话/注册实例，不允许跨会话全局可变对象。
DiscoveryResult：成功（有效候选及 validator）或失败（分类、可重试时机）；空目录须有成功且完整的源响应作为依据。

归并性质：official 始终保留；同一补充幂等；官方出现同身份时补充退出；网络失败不能减少官方集合。多个 operation/同名不同实例互不混用。

## 4. 正确性论证 R

Q1 由来源识别+原鉴权转发承担；Q2 由实际刷新生命周期而非 turn 搭车承担；Q3 由每次读取当前 O 的差集承担；Q4 由运行时层+独立缓存承担；Q5 由来源验证/兼容政策承担；Q6 由 last-good、会话代次和只读官方层承担。

该论证依赖真实接线：若 profiles 的加载顺序、首次 CLI 解析或禁用恢复不能通过公开接口满足，本架构尚未成立。不得回退到写 models.json、猴子补丁全局原型或修改其他插件；须向主会话报告具体缺口。

## 5. 先完成的机制门

在隔离临时 agent dir、无真实凭据、无付费调用条件下，用实际宿主 SDK/loader/faux provider 证明：
1. profiles 与插件两种加载顺序均保留原身份/鉴权/transport。
2. 缓存补充在启动选模型/普通 refresh 时可见；缓存阶段无外部等待。
3. 改变底层官方集合后一次刷新自动退让，官方参数原样保留。
4. 插件禁用或 reload 不留重复包装/旧任务；其他 provider 不受影响。
5. 所有写入只在临时插件缓存；models.json、认证和官方 store 内容不变。

机制 agent 只返回试验依据、准确 API/时序和拟议叶子函数签名，不得修改本文件或开始产品实现。通过 contact_supervisor 交给主会话；由主会话补齐详细设计、expectations 并决定是否放行。失败是架构阻塞，不是允许交付阉割版。

## 6. 细化与验收义务

用户最新确认的最终标准见 acceptance.md：逐返回/失败路径做代码级原行为回退与残留隔离论证；最终由用户亲验真实 GLM-5.4 自动发现及无痕正常使用。以下 faux 链路仅为实现阶段证据，不是最终验收。主会话负责把该标准写入详细设计与 expectations，不能按旧代理任务降低标准。

放行前 detailed-design.md 必须包含每个非平凡函数的签名、pre/post/副作用、分支与退出、callee 契约、循环终止、正确性论证。expectations.md 按 workflow 十节固定原始合同与测试映射。设计由独立 reasoner 一次检查，不形成互相追加要求的循环。

首条纵向链路覆盖智谱 Coding 的具名账号→发现 glm-5.4→普通 refresh 可选→通过保留的 provider 实际请求路径调用 faux transport→官方接管退出。此证据只证明本地接线，不得冒充真实 GLM 远端调用成功。网络源用可复现 mock HTTP 验证分页、401/429、断网、坏正文、304 缺体、套餐区分、非聊天过滤和兼容规则。

还须覆盖：首装无缓存、重启恢复、已有元数据更新、用户配置字节不变、两个进程共享缓存、旧 job 迟到、PI_OFFLINE、print 模式退出、禁用恢复、scope 不被擅改。真实官网抓取证据与模拟源证据分别报告；未适配来源不得宣称支持全部 providers。

实现仅使用必要测试：修改的测试逐个运行；代码改动运行 npm run check（完整输出），不跑 npm test/全套 vitest，不修无关错误、不安装或增加依赖、不提交 git。若需 dist 先按项目规定 build。测试/编译失败须给退出码与完整产物位置。

## 7. 通信语义

短连接只读目录；明确超时和 AbortSignal，按源策略退避，不无限重试；请求失败不推断撤回模型。缓存写入提交后才能替换内存快照；过期代次不得提交。官方认证及调用仍归原 provider；单飞控制在会话实例内，跨进程缓存写入需防止坏文件，不以原子 rename 冒充用户配置事务安全。
